这个问题之前也出现过几次：装在 `%LOCALAPPDATA%\Programs`（也就是 `C:\Users\<用户名>\AppData\Local\Programs`）下的软件，比如 Obsidian、DeepSeek Harness、Antigravity，突然都打不开了。双击没反应，或者窗口一闪就退。

它们有两个共同点：都是 Electron 应用，都装在用户目录下而不是 `C:\Program Files`。这次终于把原因查清楚了，记录一下。

## 现象

### 1. 沙箱进程读不到安装目录

从命令行启动 DeepSeek Harness，能看到 Electron 直接报 `FATAL` 退出：

```text
[FATAL:electron\shell\browser\win\install_dir_access.cc:52]
Sandboxed processes cannot read C:\Users\<用户名>\AppData\Local\Programs\DeepSeek Harness:
its ACL has an entry for an AppContainer package SID but none for ALL APPLICATION PACKAGES,
so Windows denies the sandbox token access.
Grant it with: icacls "C:\Users\<用户名>\AppData\Local\Programs\DeepSeek Harness" /grant *S-1-15-2-1:(OI)(CI)(RX)
```

这条报错信息量很大，原因和解法都写在里面了，后面基本就是在验证它。

### 2. GPU 进程问题


另一些应用不报上面那条 `FATAL`，症状落在 GPU 上：启动后白屏或者直接退出，日志里是 GPU 进程相关的错误。

一开始我以为是显卡驱动或硬件加速的问题，其实不是。Electron 的 GPU 进程也是**沙箱子进程**，和渲染进程一样要从安装目录读 `d3dcompiler_47.dll` 这类文件。安装目录读不了，GPU 进程起不来，主进程反复重试失败后就退出了。所以根源和第 1 条是同一个，只是报错的位置不同。

加 `--disable-gpu` 启动参数可能会让部分应用勉强能用，但渲染进程还是在同一个沙箱里，这只是绕开症状，问题本身没解决。

## 排查：看一眼 ACL

用 `icacls` 看 `AppData\Local` 的权限（SID 太长，下面用占位符代替）：

```powershell
icacls "$env:LOCALAPPDATA"
```

```text
C:\Users\<用户名>\AppData\Local <计算机名>\CodexSandboxUsers:(OI)(CI)(M)
                                 S-1-5-21-<用户 SID>:(OI)(CI)(M)
                                 S-1-15-2-<Package SID 1>:(F)
                                 S-1-15-2-<Package SID 1>:(OI)(CI)(IO)(F)
                                 S-1-15-2-<Package SID 2>:(F)
                                 S-1-15-2-<Package SID 2>:(OI)(CI)(IO)(F)
                                 （还有两个 S-1-15-2-... 条目，形式相同）
                                 NT AUTHORITY\SYSTEM:(OI)(CI)(F)
                                 BUILTIN\Administrators:(OI)(CI)(F)
                                 <计算机名>\<用户名>:(OI)(CI)(F)
```

正常的用户目录只有最后三条（SYSTEM、Administrators、用户本人），这里多出来的是：

- `CodexSandboxUsers` 组和一个对应的用户 SID：本地跑过的沙箱工具（Codex Sandbox）创建的。
- 4 个 `S-1-15-2-<一长串数字>`：这是 **AppContainer Package SID**，每个代表一个具体的沙箱容器。它们带着 `(OI)(CI)` 继承标志，所以 `AppData\Local` 下的所有子目录，包括 `Programs` 和里面每个应用的安装目录，都会继承这几条权限。

缺的是一条：**`ALL APPLICATION PACKAGES`**（SID 为 `S-1-15-2-1`）。

## 原因

把上面的信息串起来：

1. **沙箱工具改了父目录的 ACL。** 它给 `AppData\Local` 加了 4 个具体的 AppContainer Package SID，并设成可继承。
2. **AppContainer 的访问检查是白名单式的。** AppContainer 沙箱里的进程拿着一个受限 token，普通的"用户本人可读"对它不算数，ACL 里必须明确授权给它的 Package SID，或者授权给所有容器的 `ALL APPLICATION PACKAGES`，它才能读。这里只有别人的 Package SID，没有 `ALL APPLICATION PACKAGES`，所以 Electron 的沙箱子进程（Renderer / GPU / Utility）读不到自己的安装目录。
3. **Electron 启动时会先做这项检查。** DeepSeek Harness 用的是 Electron 44.7.0，它在 `install_dir_access.cc` 里预先检查安装目录的 ACL。发现"有具体 Package SID、没有 `ALL APPLICATION PACKAGES`"，就直接 `FATAL` 退出，并把修复命令打印出来。没有这项检查的应用，就表现为上面那种不明不白的 GPU 崩溃或白屏。

这也解释了为什么只有装在 `AppData\Local` 下的应用出问题：`C:\Program Files` 的 ACL 默认就带着 `ALL APPLICATION PACKAGES` 的读取和执行权限，不受影响。

## 解决：修 `Programs`，不修 `AppData\Local`

报错里给的命令只修 DeepSeek Harness 一个目录，下次装别的应用还会再遇到。源头虽然在 `AppData\Local`，但最合适的修复位置是它下面的 `Programs`：

- **不要给整个 `AppData\Local` 加这条权限。** 那里还有浏览器的用户数据、各种客户端的本地缓存和登录凭据，让所有沙箱都能读，范围太大了。
- **`Programs` 正合适。** 它相当于用户级的 `C:\Program Files`，里面只有程序本体，没有隐私数据。给它补上和 `Program Files` 一样的权限，安全上没有额外损失。

在 PowerShell 里执行一条命令（不需要管理员权限，目录归当前用户所有）：

```powershell
icacls "$env:LOCALAPPDATA\Programs" /grant "*S-1-15-2-1:(OI)(CI)(RX)"
```

参数的意思：

- `*S-1-15-2-1`：`ALL APPLICATION PACKAGES`。前面的 `*` 表示后面是 SID 而不是账户名，在中文系统上也不用操心账户名怎么写。
- `(OI)(CI)`：对象继承和容器继承。`Programs` 下已有的应用目录和文件会一起继承这条权限，以后新装的应用也会自动带上。
- `(RX)`：只给读取和执行，不给写入。

## 验证

再看一下 `Programs` 和应用目录的权限：

```powershell
icacls "$env:LOCALAPPDATA\Programs"
icacls "$env:LOCALAPPDATA\Programs\DeepSeek Harness"
```

```text
C:\Users\<用户名>\AppData\Local\Programs APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(OI)(CI)(RX)
                                          ...

C:\Users\<用户名>\AppData\Local\Programs\DeepSeek Harness APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(I)(OI)(CI)(RX)
                                                           ...
```

`Programs` 上多了 `ALL APPLICATION PACKAGES:(OI)(CI)(RX)`，应用目录里这条带着 `(I)`，说明是从 `Programs` 继承下来的。之后 Obsidian、DeepSeek Harness、Antigravity 都能正常启动了。

## 小结

- 装在 `AppData\Local\Programs` 下的 Electron 应用集体打不开，先跑一下 `icacls "$env:LOCALAPPDATA"`，看看有没有多出来的 `S-1-15-2-...` 条目。
- 根源是沙箱类工具往父目录写了具体的 AppContainer 权限，而且是可继承的。
- 修复只要一条命令，给 `Programs` 加上 `ALL APPLICATION PACKAGES` 的只读执行权限。不要扩大到整个 `AppData\Local`。
- 如果以后不再用那个沙箱工具，可以考虑把它在 `AppData\Local` 上留下的条目清掉。还在用的话它大概率会写回来，修 `Programs` 就够了。
